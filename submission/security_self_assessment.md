# Security self-assessment

Implemented boundaries include synthetic data disclosure, consent in the interface, backend demo roles, strict action validation, exact-payload approvals, scoped mandates, protected obligations, persistent execution state, outcome verification and hash-chain integrity checking. The tests and evaluation report document the checks actually exercised.

No real payment, customer notification, banking credential, credit application or proprietary WeBank data is involved. Contacts use reserved synthetic domains. API credentials remain backend environment configuration and are excluded from version control. Model requests should contain synthetic, minimized context only.

User accountability is explicit: owners inspect parameters before authorizing execution. Forecast improvement, delivery, recorded receipt and verified cash coverage are different states. The verifier does not accept an LLM statement as evidence of recovery.

The identity switcher is a demonstration aid with backend role checks, not identity verification. Local binding is the intended deployment. There is no production login, regulatory certification, external log anchor, penetration-test certification or universal prompt-injection guarantee. Docker and live-model verification limits are listed in `known_limitations.md`.
